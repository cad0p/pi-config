Authority

AI agents can propose actions. They should not be able to grant themselves the authority to execute them.

The agent is capable. The authority is external. Seal checks each action against what a person approved, before it runs, and signs the outcome either way.

Refusing an action before it runs is now common. A reviewer also needs a record they can check themselves, offline, against a published key.

One payment

  • Payments€4,800 to the invoice’s account, not a new one.
  • Software releasesA deploy to production waits for the approval and the release report.
  • RecordsA supplier’s bank details change only with a named approver.
  • Coding agentsRisky commands from Claude Code or Cursor are checked first, for invited testers.

One boundary for any action an agent takes. The payment is just the easiest one to picture.

What Seal binds

  • The actionThe tool and a hash of its exact arguments are in the signed record.
  • Required evidenceA rule can refuse an action unless named fields are present, such as an approver or a release report.
  • The approverA grant must be signed by a designated approver. A grant the agent signs for itself is refused by name.
  • Use limitsA grant can be used a set number of times. Each use is claimed once; the next attempt is refused and signed.
  • Exact-action approvalIn testingAn approval bound to one exact action and signed on the approver’s own device.

What a record does not prove

  • A signature proves what was decided and that the record was not changed. It does not prove the rule was right.
  • It covers actions routed through Seal. An action that never reaches Seal leaves no record.
  • Proving that no decision was left out of the log is an open problem. We publish it as one.
